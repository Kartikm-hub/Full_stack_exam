# @focus-mode/protocol

**Contracts only. No business logic, no transport, no side effects.**

This package is the single wire contract shared by the three Focus Mode
components: the React dashboard (`client/`), the cloud API (`server/`) and the
Electron agent (`agent/`). It exists so those three cannot invent three
different message formats.

## Why it exists

The dashboard and the agent talk over a localhost WebSocket, and the agent also
reports state to the cloud API. Those messages cross a trust boundary and drive
real changes on someone's machine. When a payload shape is written down once,
here, then a mistake becomes a validation error instead of a malformed command
that partially enforces the wrong allow-list.

The rule this package enforces: **reject, never repair.** A message that is
almost valid is invalid. Silently defaulting a missing `commandToken`, or
coercing a `null` payload to `{}`, is how a focus session ends up enforced with
the wrong policy.

## Install / import

```js
// Node (server, agent)
import { createEnvelope, validateMessage, ERROR_CODES } from '@focus-mode/protocol'

// In the browser (client, via the Vite alias)
import { AGENT_STATES, FOCUS_SESSION_STATES } from '@protocol'
```

## Envelope

Every message, in both directions:

```jsonc
{
  "version": 1,
  "type": "focus.enter",
  "id": "msg_1f0c9b1e-...",   // unique per message, generated by the sender
  "replyTo": null,              // id of the message being answered
  "timestamp": "2026-01-01T10:00:00.000Z",
  "payload": {}
}
```

| Field | Rule |
| ----- | ---- |
| `version` | Required integer. Must be in `SUPPORTED_PROTOCOL_VERSIONS` (currently `[1]`). |
| `type` | Required string, must be a known `MESSAGE_TYPES` value. |
| `id` | Required non-empty string, max 128 chars, unique per message. |
| `replyTo` | Non-empty string or `null`. |
| `timestamp` | Required ISO-8601 instant with `Z` or an offset. |
| `payload` | Plain object, possibly empty. Never `null`, never an array. |

Validation order matters: `version` is checked **first**, because an unknown
version means the rest of the message cannot be trusted. A version mismatch
returns `UNSUPPORTED_VERSION` even when the type is also nonsense.

### API

| Function | Purpose |
| -------- | ------- |
| `createEnvelope({ type, payload, id, replyTo, timestamp, version })` | Build a message. Throws `ProtocolError` on a bad type, id or `replyTo`. |
| `createReply(request, type, payload)` | Build a response linked via `replyTo`. |
| `createMessageId()` | New `msg_`-prefixed UUID v4. |
| `createTimestamp(at?)` | ISO-8601 instant string. |
| `validateEnvelope(value)` | Structure only. `{ ok: true, envelope }` or `{ ok: false, code, message, detail? }`. |
| `validateMessage(value)` | **What receivers should call.** Envelope plus payload contract. |
| `validatePayload(type, payload)` | Payload contract for one type. |
| `isValidTimestamp` / `isSupportedVersion` / `isKnownType` | Individual predicates. |

A missing `payload` or `replyTo` normalises to `{}` / `null`; everything else is
rejected. Validation never mutates the input.

## Naming convention

`pair.*`, `focus.*`, `state.*`, plus protocol-level `getState`, `ping`, `pong`,
`error` and `session.state`. A trailing `.accepted` means "validated, work
starting"; the bare form means "done, confirmed".

| Type | Direction | Purpose |
| ---- | --------- | ------- |
| `pair.request` | client → agent | Redeem the short-lived 6-digit code |
| `pair.result` | agent → client | `paired` or a vague rejection |
| `unpair.request` | client → agent | Drop the stored credential |
| `getState` | client → agent | Read-only state request |
| `state.result` | agent → client | Full state snapshot, the UI's source of truth |
| `state.push` | agent → client | Unsolicited change (tray exit, watchdog, timeout) |
| `session.state` | agent → client | Session state-machine snapshot |
| `focus.enter` | client → agent | `enterFocus(allowList)` |
| `focus.enter.accepted` | agent → client | Validated, enforcement starting |
| `focus.entered` | agent → client | OS adapter confirmed enforcement |
| `focus.exit` | client → agent | `exitFocus()` |
| `focus.exit.accepted` | agent → client | Restoration started |
| `focus.exited` | agent → client | Fully restored |
| `focus.extend` | client → agent | Bounded extension |
| `ping` / `pong` | either | Liveness; a missed heartbeat arms the fail-safe |
| `error` | either | Structured failure |

Commands in `ACKNOWLEDGED_COMMAND_TYPES` always get an explicit acknowledgement
or an `error`; they are never left unanswered.

## Payload contracts

The important ones:

```jsonc
// focus.enter — authorisation only, never policy
{ "sessionId": "ses_123", "commandToken": "tok_abc" }

// focus.exit — always honoured, no confirmation field
{ "sessionId": "ses_123" }

// getState — payload is always empty
{}

// focus.extend — bounded; "indefinite" is not representable
{ "sessionId": "ses_123", "additionalMinutes": 10, "commandToken": "tok_abc" }

// ping
{ "sentAt": "2026-01-01T10:00:00.000Z" }

// error
{ "code": "TOKEN_INVALID", "message": "Token already used", "retryable": false }
```

`focus.enter` deliberately has **no** `allowList` field. The browser cannot
dictate policy: the agent re-resolves the protected baseline itself (SPEC.md
§7.8, §7.9). Sending one is rejected as an unknown field, which is the point.

Contracts use `additional: false`, so a typo like `allowedList` fails loudly
instead of silently producing an empty allow-list.

## Error codes

Fixed enum in `ERROR_CODES`. Adding one is a reviewed change to this file.

| Code | Meaning | Retryable |
| ---- | ------- | --------- |
| `INVALID_MESSAGE` | Envelope or payload structurally invalid | no |
| `UNSUPPORTED_VERSION` | Protocol version not understood | no |
| `UNSUPPORTED_MESSAGE_TYPE` | Well-formed but not in the protocol | no |
| `PAIRING_REQUIRED` | Command needs a paired device | no |
| `UNAUTHENTICATED` | Link exists, credential does not | no |
| `PAIRING_REJECTED` | Code wrong, consumed or revoked (deliberately vague) | no |
| `TOKEN_INVALID` | One-time command token not recognised | no |
| `TOKEN_EXPIRED` | Token valid but past its expiry | no |
| `SESSION_ALREADY_ACTIVE` | Idempotent no-op; caller gets current state | no |
| `SESSION_NOT_FOUND` | Unknown session id | no |
| `INVALID_STATE` | Not legal from the agent's current state | no |
| `RATE_LIMITED` | Frame or rate limit exceeded | yes |
| `INTERNAL_ERROR` | Unexpected failure; details stay local | yes |

`retryable` is a default for the sender's UI, not a promise. Credential errors
are never retryable: the same input will fail again, and retrying would
encourage brute-forcing a 6-digit code.

## State values

Two vocabularies, kept separate on purpose.

**Agent states** (`AGENT_STATES`, upper case — an in-process state reported by
`getState()`): `IDLE`, `PAIRING`, `READY`, `ENTERING`, `ACTIVE`, `EXTENDING`,
`EXITING`, `FAILED`.

**Focus session states** (`FOCUS_SESSION_STATES`, lower case — a persisted
server record that outlives the agent process, SPEC.md §6.4): `requested`,
`active`, `exiting`, `exited`, `failed`, `auto_exited`.

`active` (record) and `ACTIVE` (process) are different things.

**Exit reasons** (`EXIT_REASONS`): `USER`, `TIMEOUT`, `WATCHDOG`,
`CRASH_RECOVERY`, `AGENT_QUIT`, `ERROR`. The last five minus `USER` are the
fail-safe paths, grouped by `AUTO_EXIT_REASONS` and detected with `isAutoExit()`.

**Link states** (`LINK_STATES`): `UNAVAILABLE` only. This is a fact about the
browser's connection, not about the agent, so it is deliberately not an agent
state. Keeping it out prevents the UI from claiming a healthy machine when
nothing has confirmed it (SPEC.md §7.22).

Predicates: `isAgentState`, `isFocusSessionState`, `isExitReason`, `isEnforcing`
(a session is open, so keep End reachable), `isAutoExit`, `isTerminalAgentState`.

## Which components consume it

| Component | When | How |
| --------- | ---- | --- |
| `client/` | Prompt 010+ | Imports constants and helpers via the `@protocol` Vite alias. Owns no transport yet. |
| `server/` | Prompt 004+ | Imports `ERROR_CODES`, `FOCUS_SESSION_STATES`, `EXIT_REASONS` for model validation. |
| `agent/` | Prompt 016+ | Calls `validateMessage` on every inbound frame and `createEnvelope` for replies. |

## Intentionally not implemented

No WebSocket server or client, no pairing logic, no session state machine, no
timers or watchdog, no Electron, no OS control, no process blocking, no database
and no Express routes. Those are Prompts 004–024. This package only says what a
valid message looks like.
